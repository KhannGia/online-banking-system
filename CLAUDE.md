# Cyclone

Blockchain term-deposit protocol + React dApp. See `README.md` for the full overview,
`contract/README.md` §7 for design answers, `docs/REQUIREMENTS.md` for traceability.

## Project memory (MCP `memory` server)

A knowledge graph for this project is available through the `memory` MCP server.
Use it — it does not update itself.

**At the start of a session**, before planning non-trivial work, call `read_graph`
(or `search_nodes` with the area you are about to touch) to load what is already known.

**During and at the end of a session**, record anything that a future session would
otherwise have to rediscover:

- decisions and their rationale ("chose X over Y because Z")
- non-obvious constraints, gotchas, and failed approaches
- conventions agreed with the user
- how a subsystem actually fits together, once traced

Use `add_observations` to extend an existing entity; `create_entities` only for something
genuinely new. Check with `search_nodes` first so entities are not duplicated.

**Do not record**: anything already in the code, the README, or git history; transient
state like "currently debugging X"; secrets, private keys, or `.env` values.

## Conventions

- Contract bindings under `frontend/src` are generated by the wagmi CLI
  (`npm run codegen`) — never hand-edit them; change `wagmi.config.ts` instead.
- The personal-variant parameters (225 bps APR, 550 bps early-withdraw penalty,
  180-day tenor, 3-day grace) are derived from student ID K234141651 and must stay
  consistent across contracts, tests, deploy script, and docs.
- Contract coverage must stay above 90%.
