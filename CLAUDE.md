# Cyclone

Blockchain savings/lending protocol + React dApp.

The project is mid-rewrite. **v1** is the finished, graded term-deposit protocol
(`SavingCore` + `VaultManager`, fixed APR, bank-funded interest vault) — tagged
`v1.0-submission`. **v2** replaces it with an Aave-v4-style hub-and-spoke architecture: one
immutable liquidity Hub that every product plugs into as a Spoke, with variable
(utilisation-driven) yield instead of a fixed APR.

Start here:

- `docs/specs/2026-08-01-hub-spoke-lending-design.md` — **the v2 design of record.** Read
  before touching anything under `contracts/hub/` or `contracts/spoke/`.
- `README.md` — v1 overview · `contract/README.md` §7 — v1 design answers ·
  `docs/REQUIREMENTS.md` — v1 traceability.
- `/home/khangia/bantu/aave-v4` — the reference implementation v2 is modelled on. Its
  `docs/overview.md` and `src/hub/interfaces/IHubBase.sol` are the useful entry points.

## Project memory (MCP `memory` server)

A knowledge graph for this project is available through the `memory` MCP server.
Use it — it does not update itself.

**At the start of a session**, before planning non-trivial work, call `read_graph`
(or `search_nodes` with the area you are about to touch) to load what is already known.

**During and at the end of a session**, record anything that a future session would
otherwise have to rediscover:

- decisions and their rationale ("chose X over Y because Z")
- non-obvious constraints, gotchas, and failed approaches
- conventions agreed with the user
- how a subsystem actually fits together, once traced

Use `add_observations` to extend an existing entity; `create_entities` only for something
genuinely new. Check with `search_nodes` first so entities are not duplicated.

**Do not record**: anything already in the code, the README, or git history; transient
state like "currently debugging X"; secrets, private keys, or `.env` values.

## Everything runs in Docker

**All dependencies live inside the container. Never install anything on the host** — no
`npm install`, no `yarn`, no populating host-side `node_modules`. The host's
`contract/node_modules` and `frontend/node_modules` are empty mount points; the real
dependencies live in Docker named volumes, so host-side `npm test` fails with
`hardhat: not found`. A host tool that needs dependencies belongs in `Dockerfile.dev`.

```bash
docker compose up -d           # start
docker compose exec dev bash   # shell inside
```

Two things to remember when running commands in the container:

- Files it creates land on the host owned by `root`. Fix with
  `docker compose exec -T dev bash -lc 'chown -R 1000:1000 <path>'` (`1000:1000` is the host
  user). The host has no passwordless `sudo`, so this must be done from inside the container.
- `bash -lc` starts a login shell, which re-sources `/etc/profile`. `PATH` additions made via
  Dockerfile `ENV` are lost there — that is why Foundry is also exported from
  `/etc/profile.d/foundry.sh`.

## Toolchains

**Hardhat** owns build, deploy, and codegen — the frontend's wagmi pipeline reads
`contract/deployments/`. **Foundry** exists only for fuzz and invariant tests against the
Hub's share accounting; it is pinned to v1.7.1 in `Dockerfile.dev`.

Both compile the same `contracts/` tree, with deliberately separate output directories
(`artifacts/`+`cache/` vs `forge-out/`+`forge-cache/`).

`contract/foundry.toml` copies the solc settings from `hardhat.config.ts` byte-for-byte
(0.8.28, optimizer runs 1000, viaIR, cancun). **If you change one, change the other** —
otherwise Foundry proves properties about bytecode Hardhat never deploys.

`forge-std` is a git submodule at `contract/lib/forge-std`; a fresh clone needs
`git submodule update --init` or `forge test` fails.

## Conventions

- Contract bindings under `frontend/src` are generated by the wagmi CLI
  (`npm run codegen`) — never hand-edit them; change `wagmi.config.ts` instead.
- Contract coverage must stay above 90%.
- v2 contracts follow `aave-v4/src/`'s layout: `contracts/hub/`, `contracts/hub/libraries/`,
  `contracts/spoke/`, `contracts/interfaces/`, `contracts/mocks/`. v1 lives on untouched under
  `contracts/v1/`.
- **Rounding in share accounting always favours the protocol** — what a user receives rounds
  down, what a user owes rounds up. See the design spec §2.3; getting this backwards is
  drainable, not cosmetic.
- The personal-variant parameters (225 bps APR, 550 bps penalty, 180-day tenor, 3-day grace,
  derived from student ID K234141651) apply to **`contracts/v1/` only**. They are retired in
  v2, where plan parameters are ordinary configuration.

## Commands

All commands run inside the container (`docker compose exec dev bash`), from `/workspace`.

```bash
cd frontend && npm run dev        # Vite dev server on :5173
cd frontend && npm test           # vitest
cd frontend && npm run codegen    # regenerate wagmi bindings

cd contract && npx hardhat test   # hardhat suite
cd contract && npm run node       # local hardhat node on :8545
cd contract && npx hardhat coverage

cd contract && forge test         # fuzz + invariant suite
cd contract && forge build
FOUNDRY_PROFILE=fast forge test   # no viaIR, ~10x faster compile, for iteration
FOUNDRY_PROFILE=ci forge test     # 10000 fuzz runs
```
